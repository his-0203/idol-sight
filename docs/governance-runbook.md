# 거버넌스 런북 — 위기 알림 대응 & 데이터 보존

이 시스템은 경쟁사·자사 아이돌·2차 창작을 추적한다. 위기 알림 오탐(특히 본체/
신원)은 **법무·PR 리스크**(Streisand). 윤리 가이드라인(`docs/superpowers/specs/
2026-05-04-v2-roadmap.md` §7)의 운영 절차본.

## 위기 알림 → 인간 검증 → 대응 (필수)

알림(`identity_leak`, `model_theft`, `controversy_spike`)은 Discord 로 **자동 발사**
되지만, **자동 대응은 금지**. 절차:

1. **수신**: Discord 알림 도착 (alerts.yml 1일 2회 + 수동 dispatch).
2. **인간 검증** (대응 전 필수):
   - 알림 body 의 샘플 제목/출처를 **원문 확인**. 키워드 substring 오탐인지(benign 복합어는 마스킹되지만 신종 패턴 가능).
   - `controversy_spike`: 그룹별 직전 스냅샷 대비 실제 급증인지(신규/희소 그룹은 스킵되도록 가드됨).
   - `identity_leak`: 진짜 본체 노출 기사인지 vs 신상품/정체성 등 일반어.
3. **판단**:
   - **오탐** → 무대응(절대 공개 반응 금지 — Streisand). 신종 오탐 패턴이면 키워드/benign 목록 보강 이슈.
   - **진성** → 사내 위기대응 채널로 에스컬레이션(법무/PR). BI 는 *감지*까지, 대응 결정은 인간.
4. **기록**: 대응/무대응 사유를 남겨 false-positive 재발 학습.

> 절대 원칙: BI 가 본체 신상을 **저장/표시하지 않는다**(위기 키워드 감지 OK, 신상 X). 2차 창작은 **양만**, 본문 저장 금지.

## 캘리브레이션 출처 기록 규칙

Health Score의 REF·임계·percentile·가중치를 바꿀 때마다 아래 형식으로 이 섹션에 append한다.

| 변경 상수 | 이전값 → 새값 | 근거 데이터 | 결정자 | 날짜 |
|---|---|---|---|---|
| `DYNAMIC_REF_PERCENTILE` | 0.90 → 0.75 | 7개 그룹 코호트: p90 = PLAVE만 포착해 나머지가 0.05–0.1 범위에 뭉침. p75로 늘리면 하위 그룹 구간 [0–0.1] → [0–0.3] 확보 | V2.14 릴리즈 (코드 주석 `:83-93`) | 2026년 초(추정) |
| `SOV_WEIGHTS` | yt_views 0.30 / comm 0.25 / news 0.20 / sub 0.15 / twitter 0.10 → yt_views 0.33 / comm 0.28 / news 0.22 / sub 0.17 (twitter 제거) | Twitter 수집 영구 종료 후 0.10 비례 재분배 | P2c (`market_share.py:47-52`) | 2026-06 |

> **추가 규칙**: (1) 변경 상수가 여러 개면 행 분리. (2) 근거 데이터는 최소 코호트 스냅샷 날짜 또는 외부 출처를 명시. (3) 인라인 코드 주석이 이미 있으면 위치 인용으로 대체 가능.
