# 거버넌스 런북 — 위기 알림 대응 & 데이터 보존

이 시스템은 경쟁사·자사 아이돌·2차 창작을 추적한다. 위기 알림 오탐(특히 본체/
신원)은 **법무·PR 리스크**(Streisand). 윤리 가이드라인(`docs/superpowers/specs/
2026-05-04-v2-roadmap.md` §7)의 운영 절차본.

## 위기 알림 → 인간 검증 → 대응 (필수)

알림(`identity_leak`, `model_theft`, `controversy_spike`)은 Discord 로 **자동 발사**
되지만, **자동 대응은 금지**. 절차:

1. **수신**: Discord 알림 도착 (alerts.yml 1일 2회 + 수동 dispatch).
2. **인간 검증** (대응 전 필수):
   - 알림 body 의 샘플 제목/출처를 **원문 확인**. 키워드 substring 오탐인지(benign 복합어는 마스킹되지만 신종 패턴 가능).
   - `controversy_spike`: 그룹별 직전 스냅샷 대비 실제 급증인지(신규/희소 그룹은 스킵되도록 가드됨).
   - `identity_leak`: 진짜 본체 노출 기사인지 vs 신상품/정체성 등 일반어.
3. **판단**:
   - **오탐** → 무대응(절대 공개 반응 금지 — Streisand). 신종 오탐 패턴이면 키워드/benign 목록 보강 이슈.
   - **진성** → 사내 위기대응 채널로 에스컬레이션(법무/PR). BI 는 *감지*까지, 대응 결정은 인간.
4. **기록**: 대응/무대응 사유를 남겨 false-positive 재발 학습.

> 절대 원칙: BI 가 본체 신상을 **저장/표시하지 않는다**(위기 키워드 감지 OK, 신상 X). 2차 창작은 **양만**, 본문 저장 금지.

## 데이터 보존 (Retention)

| 데이터 | 현재 | 권고 |
|---|---|---|
| `access_log` (cid 방문 로그) | 무제한 누적, 인덱스 없음 | 보존 기한 정책 필요(예: 90일 후 삭제) + created_at 인덱스. cid 는 브라우저 근사(개인식별 아님) |
| `community_posts` 제목/URL | 저장(본문 X) | 제목은 집계·분류용. 본문/신상 저장 금지 원칙 유지 |
| 위기 알림 원문 샘플 | alerts.body 에 제목 일부 | 신상 포함 금지. 샘플은 triage 용 최소화 |
| `youtube_video_stats` 등 시계열 | 누적 | 비용 모니터링(상태 페이지 카운트). 필요 시 오래된 스냅샷 다운샘플 검토 |
| `live_ccv_samples` (라이브 CCV 시계열) | 라이브 중에만 적재, 무한 누적 | 집계 수치(내용 X). 180일 후 다운샘플/삭제 검토(후속). 인덱스 idx_ccv_group_time 존재 |

## 데뷔일 on-call (권고)
- 데뷔 당일·직후는 알림 빈도·트래픽 모두 급증 → 알림을 **즉시 보고 판단할 담당** 지정.
- `⚙ 상태` 페이지로 수집/집계 정상 여부도 함께 모니터.

## PM 후속 결정
1. access_log 등 보존 기한 정책 확정 + 삭제 자동화(cron).
2. 위기 에스컬레이션 채널/담당(R&R) 명문화.
3. 알림 오탐 학습 루프(운영자 confirm/reject → 키워드·임계 보강).
