# 동시기 성과 브리핑 — 가독성·오해방지 종합 개선 Implementation Plan

> **For agentic workers:** 반복 리뷰 루프형 계획. Task 1(1차 구현) 후 Task 2(3방향 페르소나 리뷰 → 수정) 루프를 아래 완료 기준 통과까지 반복, Task 3(검증·배포)로 종료.

**Goal:** (사용자 피드백 2026-07-30) ① 보완할 점 문장이 "광고 과다" 인상만 주고 원인(광고가 소수 핵심 콘텐츠에 집중 투입된 구조)을 안 알려주는 오해 해소 ② 작은 텍스트 과다·위계 부재를 타이포그래피 관점에서 전면 검수·보완 — "구구절절 말고 핵심만" ③ 자연 유입 섹션의 "제외 시 N점"을 "광고 투입 콘텐츠 제외 시"로 명확히 라벨링하고 중요도 승격 ④ 투자사·경영진 페르소나 반복 검토로 "완벽하게 이해하기 쉬운" 브리핑 도달.

## 완료 기준 (이 기준 전부 통과 = 끝)

**K1. 10초 스캔**: 각 섹션은 (제목) → (잘하고 있는 점/보완할 점 두 줄)만 읽어도 결론이 잡힌다. 리드·각주는 보조 위계로 물러난다.
**K2. 오해 제로**: 부정 신호(광고 의심·낮은 점수·하위 순위)는 반드시 원인 또는 맥락과 한 문장 안에서 만난다(데이터 파생). "광고 과다"로만 읽히고 끝나는 문장 금지.
**K3. 정직성 불변**: 가짜 수치 금지·자기공시 유지·전 그룹 대칭·판정(min)과 배지 규칙 불변. 유료 여부는 "판정(자체 추정)"임이 화면 어딘가에서 항상 공시된다.
**K4. 타이포 위계 3단**: ①섹션 제목 ②해석(잘함/보완·핵심 수치) ③보조(리드·각주·소자 수치)가 크기·색·여백으로 구분된다. text-hint 문단이 3개 이상 연속으로 붙는 구간 없음. 접을 수 있는 방법론성 각주는 접되, **제외 목록은 기본 펼침 유지**(기존 원칙).
**K5. 문장 다이어트**: 해석 문장은 1문장(최대 2절), 리드는 1줄. 같은 사실을 두 번 말하는 문단 없음.
**K6. 페르소나 통과**: 타이포그래피 전문가·투자심사역·경영진 3인 리뷰에서 Critical·Important 0.

## Global Constraints

- pnpm, `frontend/`에서 `pnpm vitest run` / `pnpm typecheck` / `pnpm build`.
- 결론·수치 하드코딩 금지(전부 데이터 파생·상수 보간). 데이터 없으면 해당 절 미표시.
- 카피: 투자사·경영진 독자, 내부 용어 금지, 기존 한국어 왜-중심 주석 톤.
- 실측 참고(시뮬레이션용): miiwan 판정 41.4(조회수 기준이 낮은 쪽), 편수 74.0(2위), 유료 판정 13~14편이 조회수 71~73% 점유, 제외 시 68~69.5(주의: 최근 창에서는 57.9로 표시된 사례 — 값은 동적), 총 성장배수 15.0×(1위), 데뷔 후 1.08×(하위), 데뷔 전 배수 13.8×, 출발선 2위.

## Task 1: 1차 구현 (사용자 지적 1·2·3)

1. **organicityVerdict.weak 원인 맥락 결합** (`src/lib/cohortHeadline.ts`): 조회수 기준이 낮아 판정이 된 경우, OrgRow의 `paid_video_count`/`paid_view_share`가 있으면 원인 절을 데이터로 결합 — 취지: "…광고 영향을 배제하기 어렵다. 다만 조회수 기준이 낮은 것은 광고를 태운 것으로 판정된 콘텐츠 {N}편에 조회수 {P%}가 쏠린 구조 탓이다 — 카탈로그 전체가 광고성이라는 뜻이 아니다." (필드 없으면 기존 문장 유지. 가드 테스트 갱신.)
2. **제외 점수 라벨·승격** (`MiiWANCohortReport.tsx` ⑤): 행 둘째 줄 "제외 시 N점" → "광고 투입 콘텐츠 제외 N점"(또는 동등 명확 라벨), 시각적으로 승격(판정 점수 다음 가는 위계 — 굵기·색). miiwanExPaid 요약 문단·틱 툴팁·캡션도 같은 라벨로 통일. "판정(자체 추정)" 공시는 캡션에 유지(K3).
3. **타이포 위계·다이어트 1차** (`MiiWANCohortReport.tsx` 전반): ui-ux-pro-max 스킬을 로드해 타이포 원칙 참조. ⓐ 섹션 리드("이걸 보면 알 수 있는 것 — …")를 1줄로 축약 ⓑ VerdictLines를 보조 텍스트와 시각 분리(여백·좌측 보더 등 기존 토큰 내에서) ⓒ text-hint 문단 연속 구간 통합·축약 ⓓ 방법론성 각주(정렬 방식·배수 계산·추정치 취급 등)는 `<details>`로 접기(제외 목록은 open 유지) ⓔ 표·막대 캡션 중복 제거. 산출물이 K1·K4·K5를 겨냥.
4. 검증 3종 통과 후 커밋 1개.

## Task 2: 3방향 리뷰 → 수정 루프 (통과까지, 최대 3라운드)

- 라운드마다: ⓐ 타이포그래피 전문가(위계·밀도·스캔 동선, ui-ux-pro-max 근거) ⓑ 투자심사역 페르소나(신뢰·반증 가능성·오해 여지) ⓒ 경영진 페르소나(10초 스캔·결정 연결) 3개 리뷰를 병렬 디스패치 — 실측값으로 렌더 문장을 시뮬레이션해 평가, Critical/Important/Minor 산출.
- Critical+Important를 모아 수정 웨이브 1회(커밋 1개) → 스코프 재리뷰.
- 3인 모두 Critical·Important 0이면 루프 종료(K6). 3라운드 후에도 남으면 잔여를 정리해 보고하고 종료 판단.
